# Speed up the test suite with installed-repo copies and a parallel runner

## Next Session

### State
- `InstallerTestCase.installed_copy(*args)` installs once per process per (installer args, os.environ) into a template repo and returns a `shutil.copytree` copy plus the template's install result; `install()` and the per-file install helpers in test_progress, test_doc_records, test_lazy_rules, test_message_nudge, test_records_cli, and test_synced_blocks use it. Copies are not recorded in HARNESS_TARGETS_FILE, so `test_update_all_updates_recorded_installs_and_prunes_missing` uses `fresh_install()`. Serial `python3 -m unittest discover -s tests` dropped from about 480s to 383s on a 10-core macOS machine; the only errors are the two `hypothesis` import failures (test_isolation_telemetry, test_session_metrics), which also fail before this change.
  - files: tests/test_installer.py, tests/test_progress.py, tests/test_doc_records.py, tests/test_lazy_rules.py, tests/test_message_nudge.py, tests/test_records_cli.py, tests/test_synced_blocks.py
- `tests/run_parallel.py` discovers tests in the parent, splits each class into chunks of at most 8 tests (`--chunk`), and runs each chunk as `python -m unittest <ids>` with cwd at the repo root and `tests/` on PYTHONPATH, `-j` workers (default cpu count). Full suite: 1220 tests in 97.3s; with HARNESS_TEXT_TESTS=1 in 90.7s, same results as serial. README documents it.
  - files: tests/run_parallel.py, README.md
